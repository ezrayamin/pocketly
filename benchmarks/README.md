## What already works

- **Both builds, side by side:** `com.pocketly.js` and `com.pocketly.kmp` (release, R8 on).
- **The `perf` build type:** release plus launch arguments, for runs that need a dataset,
  network or start tab at cold start ([benchmarking.md](../docs/benchmarking.md) §5.3).
  Same package ids as release, so it installs over it.
  ```bash
  cd apps/mobile/android && ./gradlew assembleJsCorePerf assembleKmpCorePerf -PsplitApksByAbi
  adb shell am start -W -n com.pocketly.kmp/com.pocketly.MainActivity \
    -e pocketly.tab history --ei pocketly.transactionCount 1000
  ```
- **Compute and storage timing:** `core.lastComputeMs()` and `core.lastStorageMs()` in both
  cores ([benchmarking.md](../docs/benchmarking.md) §5.2). Storage is reported separately
  because the two cores use different SQLite libraries (ADR-0009).
- **Identical datasets:** `core.resetData({ seed, transactionCount, nowMillis })` produces
  the same ledger in both cores, as verified by the contract suites.
- **Persistent data:** both cores keep a fake-server database and a local replica on disk,
  so data survives restarts. A fresh install starts empty and seeds on first launch.

## Running BM-02

Needs Flashlight (`curl https://get.flashlight.dev | bash`, binary in `~/.flashlight/bin`) and the
perf APKs installed. With more than one device attached, set `ANDROID_SERIAL`.

```bash
benchmarks/scripts/bm-02-run.sh benchmarks/results/2026-10-xx_mid-01   # ~45 min with cooldowns
npx tsx benchmarks/scripts/collect.ts benchmarks/results/2026-10-xx_mid-01
```

`bm-02-scroll.sh <package>` alone runs one iteration (prepare, scroll, verify) for a manual check.

## Pre-run

```bash
yarn fixtures
benchmarks/scripts/device-info.sh benchmarks/results/2026-10-xx_low-end-01
```
