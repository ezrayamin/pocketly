# Benchmarks

The plan is [docs/benchmarking.md](../docs/benchmarking.md). This folder holds the tooling, and each piece is filled in as its scenario becomes runnable.

| Folder | Holds | Status |
|---|---|---|
| `fixtures/` | Seeded datasets: `tx-200`, `tx-1k`, `tx-10k`, `ingest-5k` (BM-04) | ✅ Generated by `yarn fixtures` (git-ignored, reproducible byte for byte) |
| `scripts/` | `device-info.sh`, `bm-01-startup.sh`, `apk-size.ts` (BM-08), `collect.ts` → `summary.csv`/`summary.md` | ✅ Used for the 2026-10-03 baseline. `run-all.sh` and `charts.ts` still to come |
| `maestro/` | One flow per scenario | ⏳ Needs screens (M2+). `bm-01-start.yaml` works with the placeholder app |
| `macrobenchmark/` | Android test module (startup, later frame timing) | ⚠️ Builds, but unreliable on the vivo V2538, so BM-01 uses platform logs (benchmarking.md §5 note) |
| `results/<date>_<device>/` | Raw output, never edited by hand | — |

## What already works

- **Both builds, side by side:** `com.pocketly.js` and `com.pocketly.kmp` (release, R8 on).
- **Compute-only timing:** `core.lastComputeMs()` in both cores ([benchmarking.md](../docs/benchmarking.md) §5.2).
- **Identical datasets:** `core.resetData({ seed, transactionCount, nowMillis })` produces
  the same ledger in both cores, as verified by the contract suites.
