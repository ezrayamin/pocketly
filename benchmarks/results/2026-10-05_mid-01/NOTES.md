Context for the raw files in this folder. Raw files are never edited; `summary.md` and
`summary.csv` are generated by `benchmarks/scripts/collect.ts`.

## Code
- Tag **`bench/2026-10-05_mid-01`** is the commit with these results. The app code it measured
  is the same in that commit and its parent (`androidx.collection` fix); the commit adds only the
  scripts, results and docs.
- Builds: `perf` (release + launch arguments), arm64-v8a, both flavors, installed over USB.

## BM-02 (scroll History, 1,000 entries)
- `bm-02-run.sh` 5 2 → 1 warm-up + 10 measured iterations per build, alternating blocks of 2.
  Only the scrolling is measured (cold start and end check run outside Flashlight's window).
- `bm-02/run.log` is the runner's raw console output. Block start temperatures (battery):

  | Block | jsCore | kmpCore |

  The gate waited for ≤ 40 °C before blocks 5 (both builds).

## Caveats
- **Temperatures are not comparable with BM-01.** BM-01 sessions ran at 34.5–34.7 °C
  (`2026-10-04_mid-01`); BM-02 blocks started at 35.7–40.0 °C with a 40 °C gate, because
  ~75 s of continuous flinging heats the phone. Compare builds within this session only.
- **Refresh rate was not fixed.** The display offers 60/90/120 Hz modes; after the run,
  `dumpsys display` reported a 60 Hz render rate, but the setting was not pinned or recorded
  during the run. Both builds ran under the same setting, so the build comparison holds, but
  absolute frame rates may not match a later session. Later sessions pin the rate and record
  it in `device.json`.
- Frame-time tracing lost events in 2 of 20 iterations (kmpCore block 2 #1: 234 events;
  block 3 #2: 14,738). Both iterations' frame rates sit inside the rest of the distribution.
- No `dumpsys gfxinfo` jank counts in this session (added for later sessions).
