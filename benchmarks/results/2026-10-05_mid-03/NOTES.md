# Session 2026-10-05_mid-03

Context for the raw files in this folder. Raw files are never edited; `summary.md` and
`summary.csv` are generated by `benchmarks/scripts/collect.ts`. `run.log` is the runner's raw
console output for all three scenarios.

## Code
- Tag **`bench/2026-10-05_mid-03`** is the commit with these results: slice 4 plus the in-app
  harness (`apps/mobile/src/bench`). `perf` builds (release + launch arguments), arm64-v8a.

## Protocol (BM-03, BM-04, BM-06)
- `bm-harness.sh <dir> <scenario>`: 5 rounds; each round cold-starts each build once
  (alternating js, kmp) with `pocketly.bench`, 5 warm-up + 10 measured runs in-process → 50
  measured per build. Before each launch: adb check and a ≤ 40 °C gate (never needed: battery
  31.9–32.6 °C; per-launch values in each `temperatures.csv`).
- Inputs are built through the Core API in the app. Checksums in `summary.md` show both builds
  read the same input and produced the same output in every scenario.
- BM-04's payload has the same length as `benchmarks/fixtures/ingest-5k.json` (1,308,125 bytes)
  but a different checksum: the harness sends the replica's order (oldest first by date), the
  fixture uses generation order. Same transactions is likely but not verified byte for byte.

## Device
- vivo V2538, setting pinned at 120 Hz (the ROM runs Pocketly at 60 Hz; not relevant to these
  timings). Same phone state as `2026-10-05_mid-02`: airplane mode, Wi-Fi and Bluetooth off,
  on the charger. No adb reconnects were needed.

## Caveats
- Storage timings compare different SQLite libraries (op-sqlite vs SQLDelight on the platform
  SQLite; ADR-0009, benchmarking.md §3.3). Compute timings are the like-for-like comparison.
- CV > 10% on some rows (see `summary.md`): the spread is within each launch and the same in
  every round, so it's run-to-run variation in the workload, not drift.
- BM-04 peak memory isn't measured in this session.
